# 开发与发布独立验收清单

本清单用于 skill 开发、重大升级、模板变更和发布前盲验。日常文档转换使用同等技术检查作为制作者自检，但不要求另启独立智能体。验证者不得读取制作历史或修改成品。

1. 记录源文件、模板、成品的实际路径、SHA-256、格式和页数。
2. 逐条比对原始技术参数、功能、指标、单位、限制条件、图片和表格。
3. 扫描正文、表格、页眉页脚、形状、备注、批注、链接、文件名、媒体和元数据中的来源厂家身份。
   `identity_review.status=NO_SOURCE_IDENTITY_FOUND` 时，映射中不得出现 `remove_identity`、`redact_identity` 或 `preserve_sanitized_image`；出现即为证据矛盾并阻断。
4. 核验固定模板 SHA、4 个非空媒体哈希、封面开头产品型号/全称和“产 品 介 绍”为白色 `FFFFFF`、六篇章顺序与唯一性、前五章均有来源支撑内容、技术参数内容和成品文件名；只有产品资质允许无来源事实时空正文。源件含技术参数表时必须保留为无序号列表格，源件仅为审定段落时不得臆造参数名或表格结构。
5. 核验成品保持 2 分节；最后一节只承载固定封底且无正文页眉页脚或页码。
6. 以 WPS 为主引擎、Microsoft Word 为备用兼容性引擎，分别打开成品并导出 PDF；逐页转 PNG 比较，并检查封面图、底图、页码、缺图、遮挡、空档、断句、重复标题、残留占位、孤立页尾标题、标签与后续图片跨页分离和表格拆行。必须保留两条且仅两条引擎证据：WPS `role=primary`、`required_identity=wps-writer`，Word `role=backup_compatibility`、`required_identity=microsoft-word`，两者均须 `identity_verified=true`、`ownership_verified=true`。任一引擎缺失或证据不完整都阻断正式交付。
   成品 OOXML 中六个固定章节标题必须显式包含 `w:keepNext`；正文标签或段落后紧跟图片容器时，该段落也必须显式包含 `w:keepNext`。这两个结构检查用于预防 WPS/Word 的页尾孤立标题和标签图片跨页分离，仍不能替代双引擎逐页视觉验收。
   若独立验证运行在隔离账户或沙箱，其自身 HKCU/COM 视图只作为限制说明，不覆盖宿主桌面用户的当前环境事实；应核验宿主桌面安装后报告、真实导出身份、进程所有权、文件哈希与逐页渲染证据。
7. 输出 `PASS`、`FAIL`、`HUMAN_REVIEW` 或 `BLOCKED`。没有完整渲染证据不得判 `PASS`。
